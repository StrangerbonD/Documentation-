JWT Authentication & Authorization

সম্পূর্ণ ২৮টি বিষয় একত্রে
ASP.NET Core & C#

1. Authentication কী?

Authentication মানে হলো কোন user সেটা verify করা।

সহজভাবে বললে:

"তুমি আসলে কে?"

ধরো, তুমি একটা website-এ login করছো:

Login Credentials
Username: Bondhon
Password: ********

Server database থেকে check করবে:

Server Flow
Username ঠিক আছে?
        ↓
Password ঠিক আছে?
        ↓
হ্যাঁ → User authenticated
না  → Login failed

অর্থাৎ Authentication user-এর identity verify করে।

Real-life example

ধরো তুমি university-তে ঢুকতে গেলে security guard তোমার ID card দেখলো। সে check করছে: "তুমি আসলেই এই university-এর student কি না?" এটাই Authentication-এর মতো।

2. Authorization কী?

Authentication-এর পর আসে Authorization। Authorization-এর প্রশ্ন হলো:

"তুমি কী কী করতে পারবে?"

ধরো দুইজন user আছে:

Users
Bondhon → Admin
Rahim   → User

দুজনই successfully login করতে পারবে। কিন্তু:

Permissions
Admin
→ User delete করতে পারবে
→ Admin page দেখতে পারবে
→ User manage করতে পারবে

User
→ নিজের profile দেখতে পারবে
→ নিজের information update করতে পারবে
→ Admin page দেখতে পারবে না

এটাই Authorization।

সহজভাবে

Authentication → তুমি কে?
Authorization → তুমি কী করতে পারবে?

3. Authentication এবং Authorization-এর পার্থক্য

বিষয় Authentication Authorization
কাজ User-এর identity verify করা Permission check করা
প্রশ্ন তুমি কে? তুমি কী করতে পারবে?
Example Login Admin page access
কখন হয় সাধারণত আগে Authentication-এর পরে
Flow
Login
  ↓
Authentication
  ↓
User কে জানা গেল
  ↓
Authorization
  ↓
User কী করতে পারবে সেটা check

4. JWT কী?

JWT-এর full form হলো: JSON Web Token

JWT হলো এমন একটা token format, যেটা ব্যবহার করে client এবং server-এর মধ্যে user-এর authentication information securely পাঠানো যায়।

সহজভাবে ধরো:

JWT Lifecycle
User login করলো
       ↓
Server username/password verify করলো
       ↓
Server একটা JWT তৈরি করলো
       ↓
Client JWT সংরক্ষণ করলো
       ↓
পরের protected request-এ JWT পাঠালো
       ↓
Server JWT verify করলো
       ↓
User-এর request accept করলো

5. JWT কেন দরকার?

ধরো তুমি login করেছো। তারপর তুমি request করলে:

HTTP Request
GET /api/profile

Server কীভাবে জানবে যে এই request Bondhon-এর? প্রতিবার তো আবার Username এবং Password পাঠানো উচিত না। তাই login-এর পরে server একটা token দেয়।

Flow
Login
 ↓
JWT
 ↓
পরের request-এ JWT
 ↓
Server বুঝতে পারে user authenticated

6. JWT-এর Structure

একটা JWT সাধারণত তিনটা অংশ নিয়ে তৈরি:

Header.Payload.Signature

তিনটা অংশ . দিয়ে separated থাকে:

Token Structure
xxxxx.yyyyy.zzzzz

তিনটি অংশ হলো: 1. Header, 2. Payload, 3. Signature।

7. JWT Header

Header-এ token সম্পর্কে কিছু information থাকে। উদাহরণ:

JSON
{
  "alg": "HS256",
  "typ": "JWT"
}

এখানে:

  • alg → কোন algorithm দিয়ে token sign করা হয়েছে। আমাদের project-এ আমরা ব্যবহার করতে পারি: HMAC-SHA256।
  • typ → Token-এর type (JWT)।

8. JWT Payload

Payload হলো JWT-এর সবচেয়ে গুরুত্বপূর্ণ অংশগুলোর একটি। এখানে claims থাকে। যেমন:

JSON Payload
{
  "nameid": "10",
  "unique_name": "Bondhon",
  "role": "Admin"
}

এখানে: nameid → User ID, unique_name → Username, role → User-এর role। এছাড়াও token-এর expiration, issuer, audience ইত্যাদি information থাকতে পারে।

9. Claim কী?

Claim হলো user সম্পর্কে কোনো information বা statement। যেমন:

Claims Info
User ID = 10
Username = Bondhon
Role = Admin

এগুলো আলাদা আলাদা claim হতে পারে। C#-এ:

C#
new Claim(ClaimTypes.NameIdentifier, user.Id.ToString())

new Claim(ClaimTypes.Name, user.UserName)

new Claim(ClaimTypes.Role, user.Role)

এখানে: NameIdentifier → User ID, Name → Username, Role → User Role।

Claim হলো JWT-এর মধ্যে রাখা user-এর কোনো একটা information।

10. Claim Type কী?

Claim-এর একটা Type এবং একটা Value থাকে। যেমন:

C#
new Claim(ClaimTypes.Role, "Admin")

এখানে: Type → Role, Value → Admin। অর্থাৎ: Role = Admin।

11. Standard Claim এবং Custom Claim

.NET কিছু standard claim type দেয়। যেমন:

C# Standard Claims
ClaimTypes.Name
ClaimTypes.NameIdentifier
ClaimTypes.Role
ClaimTypes.Email

তুমি নিজের custom claim-ও বানাতে পারো:

C# Custom Claims
new Claim("Department", "CSE")
new Claim("Permission", "DeleteUser")

12. JWT Signature

JWT-এর third part হলো Signature:

Signature Location
Header.Payload.Signature
               ↑
            Signature

Signature তৈরি করার সময় secret key এবং একটা algorithm ব্যবহার করা হয়:

Signature Generation
Secret Key
    +
HMAC-SHA256
    +
Header + Payload
    ↓
Signature

Signature-এর উদ্দেশ্য হলো token-এর information পরিবর্তন করা হয়েছে কি না সেটা verify করা।

13. Secret Key কী?

Secret Key হলো server-এর কাছে থাকা একটা secret value। যেমন: MyVeryLongSecretKey123456

এই key ব্যবহার করে JWT sign করা হয়।

গুরুত্বপূর্ণ সতর্কতা

Secret Key client-এর কাছে পাঠানো যাবে না। এটা server-side secret হিসেবে রাখতে হবে। Production application-এ সাধারণত environment variable বা proper secret-management system ব্যবহার করা হয়।

14. JWT Generate করার Flow

আমাদের ASP.NET Core application-এ login করার পর flow হবে:

Flow Diagram
Username + Password
        ↓
Database থেকে User খোঁজা
        ↓
Password Verify
        ↓
Claims তৈরি
        ↓
Secret Key
        ↓
Signing Credentials
        ↓
JWT তৈরি
        ↓
JWT String
        ↓
Client-কে পাঠানো

15. JWT Object এবং JWT String

প্রথমে আমরা C#-এ একটা JWT object তৈরি করতে পারি:

C# JwtSecurityToken
var token = new JwtSecurityToken(
    issuer: config["JwtSettings:Issuer"],
    audience: config["JwtSettings:Audience"],
    claims: claims,
    expires: DateTime.UtcNow.AddHours(2),
    signingCredentials: creds
);

এখানে token হলো একটি JwtSecurityToken object। কিন্তু client-কে পাঠানোর জন্য এটাকে JWT string-এ convert করতে হবে:

C# WriteToken
string jwtToken = new JwtSecurityTokenHandler().WriteToken(token);

তারপর ক্লায়েন্টকে রেসপন্স পাঠানো হয়:

C# Response
return Results.Ok(new { token = jwtToken });

Client response পাবে:

Client JSON Response
{
  "token": "eyJhbGciOiJIUzI1NiIs..."
}

16. Access Token কী?

Access Token হলো এমন token যেটা ব্যবহার করে client protected API access করে। যেমন:

Access Token Flow
Login
 ↓
Access Token
 ↓
GET /api/profile
 ↓
Server token verify
 ↓
Profile data

সাধারণত Access Token-এর lifetime তুলনামূলকভাবে short রাখা হয় (যেমন: 15 minutes, 30 minutes, 1 hour)। আমাদের learning project-এ শুরুতে 2 hours দিয়েও test করা যেতে পারে।

17. Token Expiration

JWT-এর একটা expiration time থাকে। যেমন:

C# Expiration
expires: DateTime.UtcNow.AddHours(2)
এই token এখন থেকে ২ ঘণ্টা valid থাকবে।

ধরো: Login: 10:00 AM → Token expires: 12:00 PM। 12:00 PM-এর পরে server token reject করবে।

18. তাহলে Facebook-এর মতো অনেকক্ষণ Login করে থাকা কীভাবে হয়?

এখানে Access Token এবং Refresh Token-এর concept আসে।

  • Access Token: Short lifetime
  • Refresh Token: Longer lifetime
Flow
Login
 ↓
Access Token + Refresh Token
 ↓
Access Token দিয়ে API access
 ↓
Access Token expired
 ↓
Refresh Token পাঠানো
 ↓
Server Refresh Token verify করে
 ↓
New Access Token
 ↓
User আবার কাজ করতে পারে

এইভাবে user-কে বারবার username/password দিতে হয় না।

19. Refresh Token কী?

Refresh Token হলো এমন একটা credential যেটা ব্যবহার করে expired Access Token-এর বদলে নতুন Access Token নেওয়া যায়। ধরো:

  • Access Token → 15 minutes
  • Refresh Token → 7 days

15 minutes পরে: Access Token expired → Refresh Token valid → New Access Token। তাই user আবার login না করেও application ব্যবহার করতে পারে।

20. Role-Based Authorization

আমাদের application-এ দুই ধরনের user থাকতে পারে: Admin এবং User। Login করার সময় JWT-এর মধ্যে role claim রাখা যায়:

C# Role Claim
new Claim(ClaimTypes.Role, user.Role)

যদি user.Role = "Admin" হয়, তাহলে JWT-এর মধ্যে Role = Admin থাকবে। তারপর ASP.NET Core-এ [Authorize(Roles = "Admin")] দিয়ে Admin-only endpoint তৈরি করা যায়।

21. Admin এবং User Example

ধরো Bondhon-এর Role = Admin:

Admin Flow
JWT → Role = Admin → Admin endpoint access → Admin page (This is Admin Page)

অন্যদিকে Rahim-এর Role = User:

User Flow
User endpoint  → Hi Rahim, Welcome!
Admin endpoint → Access Denied

22. `[Authorize]` কী?

[Authorize] দিয়ে আমরা বলতে পারি:

এই endpoint access করতে authenticated user হতে হবে।
C# Authorize
[Authorize]
[HttpGet("profile")]
public IActionResult Profile()
{
    return Ok("Your profile");
}

Login না করা user এই endpoint access করতে পারবে না।

23. `[Authorize(Roles = "Admin")]`

এটা আরও specific। [Authorize(Roles = "Admin")] মানে: User authenticated হওয়ার পাশাপাশি তার role অবশ্যই `Admin` হতে হবে।

Check Logic
Authenticated?
     ↓
    Yes
     ↓
Role = Admin?
     ↓
   Yes → Allow
   No  → Deny

24. Logout কী?

Logout মানে শুধু frontend থেকে token delete করা নয়। Real application-এ session/token invalidation-এর proper strategy দরকার হতে পারে। বিশেষ করে Refresh Token ব্যবহার করলে:

Logout Flow
Logout
 ↓
Refresh Token revoke/invalidate
 ↓
Session শেষ
 ↓
User আবার login করবে

25. Browser-এর "Save Password" আর Authentication এক জিনিস নয়

এটা খুব গুরুত্বপূর্ণ। Browser-এ যদি দেখা যায় Save password?—এটা browser/password manager-এর feature। অন্যদিকে User logged in—এটা application-এর authentication state। দুটো আলাদা:

Application Authentication ≠ Browser Password Manager

একজন user logout করার পর browser saved password দেখাতে পারে, কিন্তু তার মানে user এখনও authenticated—এমন নয়।

26. Swagger এবং JWT

Swagger দিয়ে protected API test করতে JWT Bearer authentication configure করা যায়। Request সাধারণত এমন হয়:

HTTP Header
Authorization: Bearer <JWT>

Swagger UI-তে Authorize button ব্যবহার করে token দিয়ে খুব সহজেই API টেস্ট করা যায়।

28. সবচেয়ে গুরুত্বপূর্ণ বিষয়গুলো

JWT শেখার সময় এই sequence-টা মনে রাখো:

Core Sequence
Authentication
      ↓
JWT
      ↓
Claims
      ↓
Access Token
      ↓
Authorization
      ↓
Role-Based Authorization
      ↓
Token Expiration
      ↓
Refresh Token
      ↓
Logout / Revocation

আর সবচেয়ে important distinction:

Authentication তুমি কে? (Identity Verification)
Authorization তুমি কী করতে পারবে? (Permission Check)
Access Token API access করার credential
Refresh Token নতুন Access Token পাওয়ার credential
Claim User/token সম্পর্কে information
Role User-এর permission category
Signature Token পরিবর্তন করা হয়েছে কি না verify করতে সাহায্য করে
