Refresh Token Flow & Architecture

পড়ার সময়: ৮ মিনিট
মডিউল: ০৭

১. এটা কী? (What is a Refresh Token?)

আমরা জানি যে নিরাপত্তার স্বার্থে Access Token-এর মেয়াদ খুব কম রাখা হয় (যেমন: ১৫ মিনিট বা ৩০ মিনিট)। কিন্তু ১৫ মিনিট পরপর যদি ইউজারের সামনে লগইন পপআপ আসে আর পাসওয়ার্ড দিতে বলে, তাহলে ইউজারের বিরক্তি চরমে পৌঁছাবে!

এই সমস্যার সমাধান হলো Refresh Token। এটি একটি স্পেশাল, দীর্ঘমেয়াদী এবং সুরক্ষিত সিক্রেট টোকেন (যেমন: ৭ দিন বা ৩০ দিন মেয়াদী), যা ব্যবহার করে ক্লায়েন্ট কোনো ইউজার ইন্টারঅ্যাকশন ছাড়াই ব্যাকগ্রাউন্ডে সার্ভার থেকে একদম নতুন একটি Access Token সংগ্রহ করতে পারে।

২. কেন দরকার? (Why do we need it?)

  • টোকেন চুরির ঝুঁকি কমানো: Access Token প্রতি রিকোয়েস্টের সাথে নেটওয়ার্কে ট্রাভেল করে। যদি কোনো হ্যাকার Man-in-the-middle অ্যাটাকে Access Token চুরিও করে, ১৫ মিনিট পর তা অকেজো হয়ে যাবে।
  • তাত্ক্ষণিক এক্সেস বাতিল (Revocation): সাধারণ JWT স্টেটলেস হওয়ায় মেয়াদ শেষ না হওয়া পর্যন্ত সার্ভার চাইলে কোনো ইউজারকে তাত্ক্ষণিক লগআউট করতে পারে না। কিন্তু Refresh Token সার্ভারের Database-এ সংরক্ষিত থাকে। তাই কোনো ইউজারকে ব্যান করতে চাইলে বা পাসওয়ার্ড চেঞ্জ হলে সার্ভার ডাটাবেস থেকে Refresh Token ডিলিট/রিভোক করে দিলেই তার পুরো সেশন বন্ধ হয়ে যায়!
  • নিরবচ্ছিন্ন ইউজার এক্সপেরিয়েন্স (Seamless UX): ইউজার অ্যাপ ব্যবহার করছে, ব্যাকগ্রাউন্ডে টোকেন রিফ্রেশ হয়ে যাচ্ছে—ইউজার বুঝতেই পারবে না।

৩. এটা কীভাবে কাজ করে? (How does it work?)

  1. প্রথম লগইন: ইউজার লগইন করলে সার্ভার দুটো জিনিস রিটার্ন করে:
    • Access Token (১৫ মিনিট মেয়াদের JWT)
    • Refresh Token (৭ দিনের জন্য একটি ক্রিপ্টোগ্রাফিক র‍্যান্ডম স্ট্রিং, যা ডেটাবেসেও সেভ থাকে)
  2. স্বাভাবিক রিকোয়েস্ট: ক্লায়েন্ট প্রতিটা API কল-এ এই Access Token পাঠিয়ে ডাটা আনা-নেওয়া করে।
  3. টোকেন এক্সপায়ার হলে (401): ১৫ মিনিট পর Access Token এক্সপায়ার হলে সার্ভার 401 Unauthorized দেয়।
  4. Silent Refresh: ফ্রন্টএন্ডের HTTP Interceptor এই 401 ধরা মাত্রই ইউজারের অগোচরে /api/auth/refresh-token এন্ডপয়েন্টে তার Refresh Token পাঠায়।
  5. নতুন টোকেন প্রদান: সার্ভার ডেটাবেস চেক করে দেখে Refresh Token-টি ভ্যালিড কি না। ভ্যালিড হলে সার্ভার নতুন একটি Access Token এবং নতুন একটি Refresh Token ইস্যু করে (টোকেন রোটেশন)।

৪. বাস্তব জীবনের উদাহরণ (Real-Life Example)

অ্যামিউজমেন্ট পার্কের ডে-পাস ও হোটেল কি-কার্ড

ধরো তুমি একটি রিসোর্ট পার্কে গিয়েছো। রিসোর্টের মেইন ডেস্কে তোমার পাসপোর্ট দেখিয়ে তুমি একটি স্পেশাল রিসোর্ট মেম্বারশিপ কার্ড নিলে যা ৭ দিন ভ্যালিড (এটা হলো Refresh Token)।

কিন্তু পার্কের রোলারকোস্টারে চড়ার জন্য তোমাকে দেওয়া হয় কাগজের ছোট রাইড কুপন যার মেয়াদ মাত্র ১ ঘণ্টা (এটা হলো Access Token)। কুপন হারিয়ে গেলে বা ভিজে নষ্ট হয়ে গেলেও সমস্যা নেই—তুমি রিসোর্ট কার্ড দেখিয়ে ইনফরমেশন বুথ থেকে সাথে সাথে নতুন রাইড কুপন নিয়ে নিতে পারছো।

৫. কোড এক্সাম্পল (Model ও Refresh Endpoint)

Controllers/AuthController.cs (RefreshToken) 
using System.Security.Cryptography;
using Microsoft.AspNetCore.Mvc;

public class RefreshTokenRequestDto
{
    public string AccessToken { get; set; } = string.Empty;
    public string RefreshToken { get; set; } = string.Empty;
}

[HttpPost("refresh-token")]
public async Task<IActionResult> RefreshToken([FromBody] RefreshTokenRequestDto dto)
{
    // ১. ডাটাবেস থেকে রিফ্রেশ টোকেন মিলিয়ে ইউজার খুঁজে বের করা
    var user = await _dbContext.Users
        .FirstOrDefaultAsync(u => u.RefreshToken == dto.RefreshToken);

    // ২. টোকেন বিদ্যমান এবং মেয়াদ আছে কি না যাচাই করা
    if (user == null || user.RefreshTokenExpiryTime <= DateTime.UtcNow)
    {
        return Unauthorized(new { message = "রিফ্রেশ টোকেন অকার্যকর বা মেয়াদোত্তীর্ণ! পুনরায় লগইন করুন।" });
    }

    // ৩. নতুন Access Token তৈরি
    var newAccessToken = _jwtTokenService.GenerateToken(user);

    // ৪. সিকিউরিটি বেস্ট প্র্যাকটিস: Token Rotation (নতুন Refresh Token তৈরি ও আপডেট)
    var newRefreshToken = GenerateSecureRandomToken();
    user.RefreshToken = newRefreshToken;
    user.RefreshTokenExpiryTime = DateTime.UtcNow.AddDays(7);
    await _dbContext.SaveChangesAsync();

    return Ok(new
    {
        accessToken = newAccessToken,
        refreshToken = newRefreshToken
    });
}

// ক্রিপ্টোগ্রাফিক্যালি স্ট্রং র‍্যান্ডম টোকেন জেনারেটর
private string GenerateSecureRandomToken()
{
    var randomNumber = new byte[64];
    using var rng = RandomNumberGenerator.Create();
    rng.GetBytes(randomNumber);
    return Convert.ToBase64String(randomNumber);
}

৬. কোডের লাইন-বাই-লাইন ব্যাখ্যা

RandomNumberGenerator.Create() রিফ্রেশ টোকেন সাধারণত কোনো JWT নয়—এটি একটি অতি সুরক্ষিত, ক্রিপ্টোগ্রাফিক র‍্যান্ডম স্ট্রিং যাতে কেউ অনুমান করতে না পারে।
user.RefreshTokenExpiryTime <= DateTime.UtcNow সার্ভারের ডেটাবেসে থাকা মেয়াদের সাথে বর্তমান সময় তুলনা করে নিশ্চিত করা হচ্ছে যে রিফ্রেশ টোকেনের ৭ দিনের মেয়াদ এখনও পার হয়নি।
Token Rotation (user.RefreshToken = newRefreshToken) এটি একটি অত্যন্ত গুরুত্বপূর্ণ সিকিউরিটি টেকনিক! প্রতিবার যখন ইউজার রিফ্রেশ টোকেন ব্যবহার করে, পুরনো রিফ্রেশ টোকেন বাতিল করে একদম ব্র্যান্ড-নিউ একটি রিফ্রেশ টোকেন ডাটাবেসে সেভ করা হয়। এর ফলে একই রিফ্রেশ টোকেন দিয়ে কেউ একাধিকবার সুযোগ নিতে পারে না।

৭. কমন ভুলগুলো (Common Mistakes)

রিফ্রেশ টোকেন ইমপ্লিমেন্টেশনে কমন ভুল:
  • টোকেন রোটেশন না করা: একবার রিফ্রেশ টোকেন দিয়ে আজীবন নতুন এক্সেস টোকেন দেওয়া ভয়ংকর বিপজ্জনক। সবসময় একবার ব্যবহারের পরই পুরনো রিফ্রেশ টোকেন বদলে ফেলতে হবে।
  • ব্রাউজারের খোলা localStorage-এ রাখা: রিফ্রেশ টোকেন ফ্রন্টএন্ডে সবচেয়ে নিরাপদে রাখা যায় HttpOnly Cookie-র মধ্যে, যাতে কোনো ক্ষতিকর XSS জাভাস্ক্রিপ্ট স্ক্রিপ্ট এটি চুরি করতে না পারে।

৮. শর্ট সামারি (Short Summary)

রিফ্রেশ টোকেনের মূল রহস্য:

১. Access Token কম সময় বাঁচে (১৫-৩০ মিনিট), Refresh Token বেশি সময় বাঁচে (৭ দিন)।

২. Refresh Token ডাটাবেসে সেভ থাকে, তাই সার্ভার যেকোনো মুহূর্তে ইউজারের সেশন বাতিল (Revoke) করতে পারে।

৩. Token Rotation ব্যবহারের মাধ্যমে হ্যাকিং ও সেশন হাইজ্যাকিং প্রতিহত করা যায়।
