ASP.NET Core-এ JWT Setup ও Middleware

পড়ার সময়: ৮ মিনিট
মডিউল: ০৪

১. এটা কী? (What is this setup?)

আমরা জানি ক্লায়েন্ট যখন কোনো রিকোয়েস্ট পাঠাবে, সে তার Authorization: Bearer <token> হেডার দিয়ে পাঠাবে। কিন্তু আমাদের ASP.NET Core অ্যাপ্লিকেশন কীভাবে বুঝবে যে টোকেনটি আসল নাকি নকল? কীভাবে সে অটোমেটিক টোকেনটিকে রিড করবে?

এজন্য .NET-এর Program.cs ফাইলে Authentication Service এবং Middleware কনফিগার করতে হয়।

২. কেন দরকার? (Why do we need it?)

যদি আমরা এই কনফিগারেশন না করি, তাহলে প্রতিটা কন্ট্রোলার মেথডে আমাদের নিজ দায়িত্বে ম্যানুয়ালি হেডার থেকে টোকেন বের করে ডিকোড করতে হতো এবং Signature মেলাতে হতো, যা প্রচণ্ড সময়সাপেক্ষ এবং সিকিউরিটি বাগের কারণ হতে পারত।

ASP.NET Core-এর বিল্ট-ইন JwtBearer Middleware এই পুরো ভ্যালিডেশন প্রসেসটি ব্যাকগ্রাউন্ডে স্বয়ংক্রিয়ভাবে হ্যান্ডেল করে। ফলে কন্ট্রোলারের কাছে রিকোয়েস্ট আসার আগেই সে নিশ্চিত করে নেয় টোকেনটি শতভাগ ভ্যালিড।

৩. এটা কীভাবে কাজ করে? (How does it work?)

  1. ক্লায়েন্ট যখন কোনো সুরক্ষিত এন্ডপয়েন্টে রিকোয়েস্ট করে, রিকোয়েস্টটি প্রথমে ASP.NET Core-এর Middleware Pipeline-এ প্রবেশ করে।
  2. app.UseAuthentication() মিডলওয়্যার রিকোয়েস্ট হেডারের Bearer টোকেনটি খুঁজে বের করে।
  3. সার্ভারের গোপন চাবি (Secret Key) এবং TokenValidationParameters মিলিয়ে দেখে টোকেনের স্বাক্ষর ঠিক আছে কি না এবং টোকেন এক্সপায়ার হয়েছে কি না।
  4. যদি সবকিছু ভ্যালিড হয়, সে টোকেনের Claims-গুলো বের করে একটি ClaimsPrincipal অবজেক্ট বানিয়ে কন্ট্রোলারের HttpContext.User-এর মধ্যে সেট করে দেয়।
  5. পরের ধাপে app.UseAuthorization() চেক করে দেখে কন্ট্রোলারের রুলস (যেমন: Role = Admin) ইউজারের সাথে মেলে কি না।

৪. বাস্তব জীবনের উদাহরণ (Real-Life Example)

অফিসের অটোমেটিক সিকিউরিটি স্ক্যানার ও রিবন

ধরো কোনো হাই-টেক সফটওয়্যার কোম্পানিতে ঢুকতে গেলে গেটে একটা অটোমেটিক কার্ড স্ক্যানার মেশিন বসানো থাকে। কর্মীরা কার্ড ছুঁইয়ে দিলেই মেশিন সাথে সাথে কার্ডের চিপ স্ক্যান করে দরজা খুলে দেয়। রুমের ভেতরের ম্যানেজারের কাছে কর্মীকে আলাদা করে প্রমাণ দিতে হয় না যে সে অনুমোদিত কি না—কারণ গেটের অটোমেটিক সিস্টেম আগেই তা ভেরিফাই করে দিয়েছে!

ASP.NET Core-এর JwtBearer Middleware হলো সেই ডিজিটাল অটোমেটিক গেট স্ক্যানার। সে কন্ট্রোলারে ঢোকার আগেই সব চেক করে পথ ক্লিয়ার করে দেয়।

৫. কোড এক্সাম্পল (Program.cs ও appsettings.json)

প্রথমে আমাদের প্রয়োজন Microsoft.AspNetCore.Authentication.JwtBearer NuGet প্যাকেজটি ইনস্টল করা:

Terminal (CLI) 
dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer

এবার Program.cs ফাইলে Dependency Injection ও Middleware কনফিগার করি:

Program.cs (.NET 8) 
using System.Text;
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;

var builder = WebApplication.CreateBuilder(args);

// ১. Controllers সার্ভিস যুক্ত করা
builder.Services.AddControllers();

// ২. appsettings.json থেকে JWT কনফিগারেশন রিড করা
var jwtSettings = builder.Configuration.GetSection("JwtSettings");
var secretKey = jwtSettings["SecretKey"];

// ৩. Dependency Injection-এ Authentication সার্ভিস কনফিগার করা
builder.Services.AddAuthentication(options =>
{
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options =>
{
    options.TokenValidationParameters = new TokenValidationParameters
    {
        ValidateIssuer = true,
        ValidateAudience = true,
        ValidateLifetime = true,
        ValidateIssuerSigningKey = true,
        ValidIssuer = jwtSettings["Issuer"],
        ValidAudience = jwtSettings["Audience"],
        IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(secretKey)),
        ClockSkew = TimeSpan.Zero // ডিফল্ট ৫ মিনিটের গ্রেস পিরিয়ড বাতিল করে তাৎক্ষণিক এক্সপায়ার নিশ্চিত করা
    };
});

var app = builder.Build();

// ৪. Middleware Pipeline সাজানো (অত্যন্ত গুরুত্বপূর্ণ সিরিয়াল!)
app.UseHttpsRedirection();

app.UseAuthentication(); // পরিচয় যাচাই (আগে থাকতে হবে)
app.UseAuthorization();  // পারমিশন যাচাই (পরে থাকতে হবে)

app.MapControllers();

app.Run();

৬. কোডের লাইন-বাই-লাইন ব্যাখ্যা

builder.Services.AddAuthentication(...) সিস্টেমে বলে দেওয়া হচ্ছে যে আমাদের অ্যাপ্লিকেশনের ডিফল্ট অথেনটিকেশন স্কিম হবে Bearer Token।
options.TokenValidationParameters এখানে সার্ভারকে নিয়ম ঠিক করে দেওয়া হচ্ছে: ইনকামিং টোকেনের Issuer (কে পাঠাল), Audience (কার জন্য টোকেন) এবং Secret Key মিলিয়ে দেখতে হবে।
ClockSkew = TimeSpan.Zero ডিফল্টভাবে .NET সার্ভারের টাইম সিঙ্ক সমস্যার কারণে টোকেনের মেয়াদের পরেও অতিরিক্ত ৫ মিনিট পর্যন্ত টোকেন ভ্যালিড রাখে। ClockSkew = TimeSpan.Zero দিলে টোকেনের মেয়াদ ১ সেকেন্ড শেষ হলেও সাথে সাথে ইনভ্যালিড ধরা হয়।
app.UseAuthentication() & app.UseAuthorization() এইচটিটিপি পাইপলাইনে মিডলওয়্যার দুটি যুক্ত করা হলো। UseAuthentication আগে টোকেন থেকে পরিচয় বের করবে, তারপর UseAuthorization পারমিশন চেক করবে।

৭. কমন ভুলগুলো (Common Mistakes)

Program.cs কনফিগারেশনে যেসব ভুল হয়:
  • UseAuthentication() ভুলে বাদ দেওয়া: নতুনরা প্রায়ই সার্ভিস অ্যাড করে (AddAuthentication), কিন্তু পাইপলাইনে app.UseAuthentication() লিখতে ভুলে যায়! ফলে টোকেন পাঠানো সত্ত্বেও কন্ট্রোলারে 401 Unauthorized আসে।
  • UseAuthorization-এর পরে UseAuthentication লেখা: পাইপলাইনের অর্ডার অত্যন্ত গুরুত্বপূর্ণ। যদি app.UseAuthorization() আগে লেখো, তবে সে ইউজারের আইডেন্টিটি পাওয়ার আগেই অথরাইজেশন চেক করে ফেলবে এবং ফেইল করবে।

৮. শর্ট সামারি (Short Summary)

মনে রাখার মূল বিষয়:

১. NuGet প্যাকেজ Microsoft.AspNetCore.Authentication.JwtBearer ইনস্টল থাকতে হবে।

২. TokenValidationParameters দিয়ে Issuer, Audience, ও Secret Key ভ্যালিডেশন অ্যাক্টিভ করতে হয়।

৩. পাইপলাইনের স্বর্ণালী নিয়ম: UseAuthentication() আগে, UseAuthorization() পরে।
