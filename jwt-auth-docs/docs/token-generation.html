Login Controller ও Token Generation

পড়ার সময়: ৬ মিনিট
মডিউল: ০৫

১. এটা কী? (What is this?)

এটি হলো আমাদের অথেনটিকেশন আর্কিটেকচারের প্রবেশদ্বার (Entrypoint)। যখন একজন ইউজার ফ্রন্টএন্ডে তার ইমেইল আর পাসওয়ার্ড টাইপ করে "Login" বাটনে ক্লিক করে, তখন ব্যাকএন্ডের এই কন্ট্রোলার মেথডটি তার ডাটা রিসিভ করে, পাসওয়ার্ড যাচাই করে এবং নতুন একটি JWT Access Token রিটার্ন করে।

২. কেন দরকার? (Why do we need it?)

সিস্টেমকে জানতে হবে ইউজার আসল কি না। সরাসরি ডেটাবেস ওপেন করে রাখা যায় না। তাই একটি সুরক্ষিত কন্ট্রোলার এন্ডপয়েন্ট (যেমন POST /api/auth/login) এবং একটি সুনির্দিষ্ট DTO (Data Transfer Object) দরকার, যা ক্লায়েন্ট থেকে আসা ইনপুট ভ্যালিডেট করবে এবং টোকেন তৈরি করবে।

৩. এটা কীভাবে কাজ করে? (How does it work?)

  1. ক্লায়েন্ট LoginDto আকারে Email ও Password পাঠায়।
  2. কন্ট্রোলার ডেটাবেসে গিয়ে দেখে এই ইমেইল দিয়ে কোনো ইউজার আছে কি না। না থাকলে 401 Unauthorized রিটার্ন করে।
  3. যদি ইউজার পাওয়া যায়, তাহলে BCrypt বা হ্যাশিং অ্যালগরিদম দিয়ে চেক করা হয় ক্লায়েন্টের পাসওয়ার্ড আর ডেটাবেসের Password Hash মেলে কি না।
  4. পাসওয়ার্ড ম্যাচ করলে JwtTokenService কল করে টোকেন জেনারেট করে ক্লায়েন্টকে 200 OK রেসপন্সে টোকেনটি পাঠানো হয়।

৪. বাস্তব জীবনের উদাহরণ (Real-Life Example)

ব্যাংকের টোকেন কাউন্টার

তুমি ব্যাংকে টাকা তুলতে গিয়ে ক্যাশ কাউন্টারে যাওয়ার আগে রিসিপশনে তোমার চেকবই বা একাউন্ট নম্বর দেখালে। ব্যাংক অফিসার একাউন্ট মিলিয়ে দেখে তোমাকে একটি টোকেন নম্বর স্লিপ ধরিয়ে দিল। এরপর বাকি সমস্ত টেবিলে তুমি কেবল সেই টোকেন স্লিপ দেখিয়েই সার্ভিস পাবে, তোমাকে বারবার পুরো ফাইল বা এনআইডি দেখাতে হবে না!

Login Controller হলো সেই রিসিপশন কাউন্টার, যে প্রথমবার ইউজারকে চেক করে একটি গোল্ডেন টোকেন স্লিপ ধরিয়ে দেয়।

৫. কোড এক্সাম্পল (DTO ও Controller)

নিচে পরিষ্কার DTO এবং কন্ট্রোলার কোড দেওয়া হলো:

Controllers/AuthController.cs 
using Microsoft.AspNetCore.Mvc;

// ১. Login Request এর জন্য DTO
public class LoginDto
{
    public string Email { get; set; } = string.Empty;
    public string Password { get; set; } = string.Empty;
}

[ApiController]
[Route("api/[controller]")]
public class AuthController : ControllerBase
{
    private readonly IUserService _userService;
    private readonly JwtTokenService _jwtTokenService;

    public AuthController(IUserService userService, JwtTokenService jwtTokenService)
    {
        _userService = userService;
        _jwtTokenService = jwtTokenService;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginDto dto)
    {
        // ১. ইউজার খুঁজে দেখা
        var user = await _userService.GetByEmailAsync(dto.Email);
        if (user == null)
        {
            return Unauthorized(new { message = "ভুল ইমেইল বা পাসওয়ার্ড!" });
        }

        // ২. Password Hashing ভেরিফাই করা (BCrypt)
        bool isPasswordValid = BCrypt.Net.BCrypt.Verify(dto.Password, user.PasswordHash);
        if (!isPasswordValid)
        {
            return Unauthorized(new { message = "ভুল ইমেইল বা পাসওয়ার্ড!" });
        }

        // ৩. JWT Token তৈরি করে রেসপন্স পাঠানো
        var token = _jwtTokenService.GenerateToken(user);

        return Ok(new
        {
            accessToken = token,
            tokenType = "Bearer",
            expiresIn = 7200 // ২ ঘণ্টা (সেকেন্ডে)
        });
    }
}

৬. কোডের লাইন-বাই-লাইন ব্যাখ্যা

public class LoginDto সরাসরি ডেটাবেসের User Entity ব্যবহার না করে সবসময় DTO ব্যবহার করা ভালো অভ্যাস। এতে শুধু যে ফিল্ডগুলো প্রয়োজন (Email, Password) কেবল সেগুলোই ক্লায়েন্ট থেকে আসে।
BCrypt.Net.BCrypt.Verify(...) ইউজারের পাঠানো প্লেইনটেক্সট পাসওয়ার্ড এবং ডেটাবেসের হ্যাশ মিলিয়ে দেখছে। মনে রাখবে, ডেটাবেসে পাসওয়ার্ড কখনো প্লেইনটেক্সটে রাখা যাবে না।
return Unauthorized(new { message = "..." }) ইমেইল না মিললেও বা পাসওয়ার্ড না মিললেও একই জেনেরিক মেসেজ দেওয়া হচ্ছে: "ভুল ইমেইল বা পাসওয়ার্ড"। আলাদা করে "ইমেইল পাওয়া যায়নি" বললে হ্যাকাররা সিস্টেমের ভ্যালিড ইমেইল লিস্ট তৈরি করার সুযোগ পায় (User Enumeration Attack)।
return Ok(new { accessToken = token, ... }) সফলভাবে তৈরি হওয়া টোকেনটি ক্লায়েন্টকে পাঠানো হচ্ছে। ক্লায়েন্ট এটি লোকালস্টোরেজ বা মেমোরিতে সংরক্ষণ করে পরবর্তী সব রিকোয়েস্টে পাঠাবে।

৭. কমন ভুলগুলো (Common Mistakes)

কন্ট্রোলারে লগইন হ্যান্ডলিং করার সময় ভুল:
  • সরাসরি string সমান সমান (==) দিয়ে পাসওয়ার্ড চেক করা: কখনোই user.Password == dto.Password করবে না! এটি চরম বিপজ্জনক। পাসওয়ার্ড অবশ্যই সল্টসহ ক্রিপ্টোগ্রাফিক হ্যাশিং (যেমন: BCrypt/Argon2) দিয়ে ভেরিফাই করতে হবে।
  • লগইন রেসপন্সে পুরো User অবজেক্ট পাঠিয়ে দেওয়া: অনেকেই ভুল করে return Ok(new { user = user, token = token }) দেয়, যাতে ইউজারের PasswordHash ফিল্ড পর্যন্ত ফ্রন্টএন্ডে এক্সপোজ হয়ে যায়! রেসপন্সে শুধু টোকেন আর প্রয়োজনীয় পাবলিক ফিল্ড দেবে।

৮. শর্ট সামারি (Short Summary)

মূল কথা:

১. Login Controller হলো ইউজারের পরিচয় নিশ্চিত করার গেটওয়ে।

২. ইনপুটের জন্য LoginDto এবং পাসওয়ার্ড যাচাইয়ের জন্য BCrypt.Verify ব্যবহার করতে হবে।

৩. সফল লগইনে তৈরি হওয়া টোকেন accessToken প্রোপার্টিতে ক্লায়েন্টকে দিতে হবে।
